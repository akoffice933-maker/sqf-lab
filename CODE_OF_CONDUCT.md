# Code of conduct

## Our standard

Be technically honest and personally decent.

* Critique code, numbers and methods — not people.
* "Your benchmark has the key in scope" is a welcome sentence; "you are an
  idiot" is not.
* Do not overstate results, and do not ask others to.
* No harassment, no discriminatory language, no doxxing — including of puzzle
  authors or of people who run public challenges.

## Scope

This applies to issues, pull requests, discussions, commit messages and any
space where you are representing the project.

## Enforcement

Report problems to the maintainers via the security contact in
[`SECURITY.md`](SECURITY.md). Reports are handled privately. Consequences range
from a request to edit a comment to a permanent ban, depending on severity and
repetition.

## On the subject of "hacking challenges"

Public challenges invite attempts. That is not a licence to attack unrelated
services, and it is not a licence to be unpleasant to the person who set the
challenge. If a maintainer asks you to stop discussing a specific live target in
this repository, stop.
