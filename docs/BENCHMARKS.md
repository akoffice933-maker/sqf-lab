# Benchmarks — methodology, numbers, and how to reproduce them

## The three rules

Any number in this repository satisfies all three, or it is not published:

1. **Blind input.** The secret key is generated by the harness and never crosses
   the solver boundary. The solver receives `P = k·G` and `[a, b]` only.
2. **In-loop counters.** `baby_ops`, `giant_ops`, `ops` are incremented at the
   operation site. Nothing is reconstructed as `c·√W` afterwards. The C++ engines
   report `table_ops` and `search_ops` separately for the same reason.
3. **External verification.** `verified = (k == secret)` happens in the harness
   after the solver returns; the solver's own `verified` flag is never trusted.

Additional provenance recorded per run: window width, table size, wall-clock
seconds, and raw JSON committed to `benchmarks/results/`.

## Machine

* 2 vCPU (x86-64), 4 GB RAM, no GPU
* `g++ (Debian 14.2.0-19) 14.2.0`, `-O3 -fPIC -shared -fopenmp -std=c++17 -lgmp`
  with `NATIVE=0` (no `-march=native`), so the numbers are portable rather than
  machine-tuned
* Python 3.13.16, CPython, no C accelerators in the reference path

## Native engines (SQF-64 vs kangaroo variants)

`make bench-native` → `benchmarks/results/native_suite.json`

| --- | --- | --- | --- | --- | --- | --- | --- |
| SQF-64 | 1.619 | 1.061 | 1.357 | 1.095 | 1.037 | 15/15 | 6.1 – 17.0 |
| RCKangaroo (SOTA v2) | 4.082 | 4.151 | 6.159 | 4.223 | 4.492 | 15/15 | 0.8 – 8.3 |
| classic kangaroo | 4.596 | 2.724 | 3.030 | 3.750 | 2.882 | 15/15 | 1.0 – 8.1 |

Per-width detail (`ops_over_sqrt` per trial) is in the JSON; the spread at `2^32`
for RCKangaroo (4.1–8.2) is the normal variance of a probabilistic walk, and it
is reported rather than smoothed away.

## Reading the numbers correctly

* **`ops / √W` below 1.0 is normal** for SQF: the loop stops at the first hit, so
  the average is roughly half of the worst case `2√W`.
* **Comparing across widths is meaningless** without the memory column. At `2^40`
  the SQF table is ~8 MB; at `2^60` it would be ~8 TB, which is why SQF stops
  being an option long before the kangaroo does.
* **Extrapolation is the main source of fantasy in this field.** `2^70` (the
  `#140` window) at the measured 1.0·√W and 17 MEcOps/s is `2^35 / 17e6 ≈ 24
  days` of pure group operations on one core — with `2^35` bytes of table, i.e.
  not runnable at all. Quote this whenever someone claims a "breakthrough".

## Reproducing

```bash
python3 -m pip install -e ".[dev]"
make test            # 58 tests
make native          # or: make native NATIVE=1 for a tuned local build
make bench           # pure Python
make bench-native    # native engines
```

Both benchmark scripts accept `--bits`, `--trials` and `--seed`/`--out` so a
reviewer can reproduce or extend any row.
