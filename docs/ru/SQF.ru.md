# SQF по-русски: как это работает

## 1. Складывание интервала

Ищем `k ∈ [a, b]`, где `k·G = P`. Обозначим `C = ⌊(a+b)/2⌋`, `d = k − C`,
`|d| ≤ R`. Выбираем размер детской таблицы `M`. Любое `d` представимо как

```
d = q·(2M) + r,   |r| ≤ M,   |q| ≤ Q = ⌊R/(2M)⌋ + 1
```

Значит, достаточно хранить `M` точек `r·G`, а по «гигантской» оси идти шагами
`2M·G` в обе стороны от якоря `K₀ = P − C·G`.

## 2. Откуда берётся квартет

* **Детская симметрия:** `x(r·G) = x(−r·G)`. Одна запись `x ↦ r` в таблице
  отвечает сразу за `+r` и `−r`.
* **Гигантская симметрия:** поиск идёт одновременно по `q = +1, +2, …` и
  `q = −1, −2, …`.

Их произведение и есть квартет кандидатов
`{C ± q·2M ± r}`: одна проверка таблицы закрывает четыре ключа.

В коде за гигантский знак отвечает `signed_q`, за детский — цикл по `±r`,
итоговый кандидат — `C − signed_q·2M ± r`.

## 3. Зеркальная сборка таблицы

Наивно `1·G … M·G` требует `M` инверсий. Заметим, что точки
`C + j·G` и `C − j·G` имеют **общий знаменатель** `x(C) − x(j·G)`. Значит, одна
инверсия даёт две точки, а трюк Монтгомери инвертирует целый блок
знаменателей сразу. Замер: 4096 кратных за **14 инверсий**.

## 4. Стоимость

| фаза | сложений | инверсий |
| --- | --- | --- |
| таблица | `M` | `≈ 2M/B` (`B = 512`) |
| гигантские шаги | `2Q + 1` | 1 |

При `M = √(W/2)` это `≈ 2√W` в худшем случае и `≈ √W` в среднем (выход по
первому попаданию). Память — `M` x-координат.

## 5. Честные ограничения

* При `W = 2^70` (окно `#140`) это `2^35` операций и `2^35` байт таблицы —
  неисполнимо, а не «медленно».
* Складывание интервала — биекция: она не уменьшает пространство поиска.
* Любой «прорыв», который не приложил JSON из `benchmarks/results/`, считается
  несуществующим.
