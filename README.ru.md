# sqf-lab

**Лаборатория Symmetric Quartet Folding для `secp256k1`** — решатели, честный
бенчмарк-стенд, постоянный реестр с защитой от повторного прохода,
воспроизводимая реконструкция пазла и протокол всего, что *не* сработало.

[![CI](https://github.com/your-org/sqf-lab/actions/workflows/ci.yml/badge.svg)](https://github.com/your-org/sqf-lab/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-informational.svg)](pyproject.toml)

> **Чем это не является.** Это не способ вскрыть 135-битные ключи. Сложность
> дискретного логарифма на `secp256k1` — `~√N ≈ 2^128` групповых операций;
> лучшие классические алгоритмы меняют *константу*, а не показатель степени.
> Всё здесь — про честное измерение этих констант и про бухгалтерию
> (расписание, дедупликация, происхождение данных), без которой реальные
> кампании разваливаются.

---

## Зачем этот репозиторий

Большинство репозиториев с «быстрым решателем `secp256k1`» повторяют три одни
и те же ошибки: бенчмарк идёт с секретным ключом в области видимости, вместо
подсчёта операций используется формула `1.5 * sqrt(W)`, а проверка ответа
делается внутри того же цикла, который его нашёл. Здесь всё устроено ровно
наоборот:

| Правило | Где закреплено |
| --- | --- |
| решатель получает только `P = k·G` и `[a, b]` | `sqflab/bench.py` |
| каждая групповая операция инкрементируется **внутри** цикла | `sqflab/bsgs.py`, `sqflab/kangaroo.py` |
| найденный ключ сверяется с секретом **после** выхода из решателя | `sqflab/bench.py`, `benchmarks/*.py` |
| ни один диапазон и ни один ключ не проверяется дважды | `sqflab/registry.py` |
| отрицательные результаты публикуются, а не прячутся | `docs/P2G-3LTC.md`, `CHANGELOG.md` |

## Измеренные результаты (воспроизводимые)

Все цифры получены скриптами из `benchmarks/`, сырые JSON — в
`benchmarks/results/`. «ops» — всегда *посчитанные групповые операции*,
`√W` — корень из ширины окна.

### Нативные движки (`cpp/`, g++ 14.2, 2 ядра, `NATIVE=0`)

| движок | 2^24 | 2^28 | 2^32 | 2^36 | 2^40 | проверено | MEcOps/s |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **SQF-64** (таблица + гигантские шаги) | 1.62 | 1.06 | 1.36 | 1.10 | 1.04 | 15/15 | 6 – 17 |
| RCKangaroo (SOTA v2, ±отражение, L1S2) | 4.08 | 4.15 | 6.16 | 4.22 | 4.49 | 15/15 | 0.8 – 8.3 |
| классический кенгуру | 4.60 | 2.72 | 3.03 | 3.75 | 2.88 | 15/15 | 1.0 – 8.1 |

Единицы: среднее `ops / √W`.

### Чистый Python

| решатель | 2^16 | 2^20 | 2^24 | 2^26 | проверено |
| --- | --- | --- | --- | --- | --- |
| SQF-BSGS (`sqflab.bsgs`) | 0.97 | 1.14 | 1.09 | 1.06 | 12/12 |
| многопалубный кенгуру (`sqflab.kangaroo`) | 1.28 | 1.35 | 1.72 | 4.22 | 12/12 |

Два честных вывода, оба видны в таблице:

1. **До ~2^45 выигрывает таблица.** SQF требует `√(W/2)` элементов поля в ОЗУ
   (8–300 МБ в указанном диапазоне); кенгуру не требует почти ничего. Начиная
   примерно с `2^60` таблица перестаёт помещаться и остаётся только кенгуру.
2. **Константа — не главное.** На `2^70` — реальный размер окна `#140` — даже
   `1.0·√W = 2^35` операций SQF при 17 MEcOps/s это **≈ 24 суток на одном ядре,
   и 2^35 байт ОЗУ взять негде.** Никакая метафора «морского боя», нарезка бит
   или хитрое расписание этого не меняют.

## Что внутри

```
src/sqflab/          чистый типизированный core без зависимостей (58 тестов)
├── curve.py         групповая арифметика secp256k1, SEC1, Base58/WIF, hash160
├── folding.py       примитивы SQF: зеркальные кратные, x-only таблица квартетов
├── bsgs.py          решатель SQF-BSGS со счётчиками внутри циклов
├── kangaroo.py      многопалубный кенгуру (базовая линия)
├── bench.py         слепой бенчмарк (проверка вне решателя)
├── native.py        ctypes-биндинги к cpp/ (libsqf_dual.so)
├── registry.py      постоянный анти-дубликат реестр (SQLite + WAL)
├── battleship.py    модель расписания «в одном квадрате» + аудит ранений
├── p2g.py           верифицированные декодеры path-to-greatness-3ltc
└── cli.py           `python -m sqflab …`
cpp/                 движки C++17/OpenMP: SQF-64, RCKangaroo, HASH160, AES-NI оракул
apps/lottery/        эталонный HTTP-пул + клиент + инструкция для агентов
research/archive/    замороженные лабораторные скрипты (русские комментарии, жёсткие пути)
docs/                алгоритмы, бенчмарки, протокол, этика, отрицательные результаты
```

## Быстрый старт

```bash
git clone https://github.com/your-org/sqf-lab && cd sqf-lab
python3 -m pip install -e ".[dev]"

make test        # 58 тестов, ~3 с, чистый Python
make native      # сборка C++ движков в cpp/build
make test-all    # тот же набор + smoke-тесты нативной библиотеки
```

Решить 24-битное окно, зная только открытый ключ:

```bash
$ python3 -m sqflab addr --priv 0x1
address  : 1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH

$ python3 -m sqflab solve --pub 02f0…b1c4 --bits 24
k            : 0x8a3f21
ops          : 2,914 (1.021 * sqrt(W))
verified     : True
```

## Реестр анти-дубликатов

Совместный поиск имеет смысл только если два участника не могут сканировать
один и тот же скаляр. `sqflab.registry` гарантирует это двумя механизмами:
аренда всегда выдаётся строго после максимального выданного `end_k`
(`BEGIN IMMEDIATE`, поэтому ни гонка, ни падение процесса не создают
пересечение), а каждый проверенный скаляр хранится как солёный отпечаток
`blake2b` под `UNIQUE`-индексом — и никогда как сам ключ.

```bash
$ python3 -m sqflab registry --db pool.db claim --label puzzle-140 --bits 140 --span 68719476736
{ "block_id": "blk-9f1c…", "start_k_hex": "0x8000000000000000", "duplicate_prevented": false }
```

Тот же протокол по HTTP, с end-to-end тестом:

```bash
python3 apps/lottery/api.py --db pool.sqlite3 --port 8000
```

Полный протокол для автономного агента — в
[`apps/lottery/AGENT_SKILL.md`](apps/lottery/AGENT_SKILL.md).

## Реконструкция пазла `path-to-greatness-3ltc`

`sqflab/p2g.py` воспроизводит все *проверяемые* шаги охоты за 3.026 LTC
(`LUtL7qnm3gzxKjHcfVLSjydqhhinTVmTmS`): декодер A1Z26 без переполнений для
подсказки 2 (даёт инструкцию *«directions should be spelled and check the
first»*), обход сетки 10×10 `wasd`, три однозначно определённых правила
подсказки 8 по таблице треков альбома и реестр сегментов. **32-байтный
AES-ключ до сих пор неизвестен**: проверено 37 373 278 038 пар кандидатов,
ноль попаданий, и [`docs/P2G-3LTC.md`](docs/P2G-3LTC.md) фиксирует, где
именно застрял каждый сегмент.

## Этика и рамки

Инструменты ищут ключи в пространствах, которые *опубликованы как пазлы* или
*принадлежат тому, кто запускает поиск*. Граница описана в
[`docs/ETHICS-AND-SCOPE.md`](docs/ETHICS-AND-SCOPE.md): ничего из этого не
предназначено для чужих кошельков, и репозиторий сознательно **не** содержит
рабочего эксплойта для живого челленджа `stealmybitcoin.com` — разбор
`PHP2Shell` (`CVE-2026-109618` / `CVE-2026-109619`) в
[`docs/PHP2SHELL-NOTES.md`](docs/PHP2SHELL-NOTES.md) носит защитный характер.
